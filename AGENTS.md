# Ghostline Agent Guide

`AGENTS.md` and `CLAUDE.md` are intentionally identical. Keep them in sync.

## Context Budget Rules

This repo is small, but generated outputs and long history docs can waste the
context window fast. Default to targeted reads.

- Do not read full `BACKLOG.md` by default. Read headings first, then the active
  ticket section that matches the task.
- Do not read full history docs by default. Open `docs/PROJECT_STATE.md` only when
  current status or architecture matters; open `docs/RL_EXPERIMENT_LOG.md` only for
  RL experiment history.
- The old monolithic design doc was removed after the design had been built. Durable architecture rules
  now live in this file and `docs/PROJECT_STATE.md`.
- Avoid searching generated artifacts unless the task is about analytics, replays,
  or outputs:

```powershell
rg "pattern" --glob "!runs/**" --glob "!replays/**" --glob "!.pytest_cache/**"
```

## North Star

Ghostline is a deterministic 2D top-down time-trial racer and RL sandbox. Protect:

- fun human driving now,
- deterministic replay/ghost/action validation,
- clean RL wrappers later,
- the pure sim/render separation.

When in doubt, preserve determinism, the `Action` seam, and `core/` purity.

## Startup Workflow

1. Read this file.
2. If the user asks "what next", planning, or task management: inspect `BACKLOG.md`
   headings and read only the relevant open ticket.
3. If status is unclear: read `docs/PROJECT_STATE.md`.
4. If the task is RL training/result interpretation: read the relevant part of
   `docs/RL_EXPERIMENT_LOG.md` or current `runs/rl/analysis/ranked_runs.md`.
5. Read nearby code/tests for the area you are changing.
6. Make the smallest scoped change that fits existing patterns.
7. Add or update focused tests for behavior changes.
8. Run the tight check first, then broader checks.

## Commands

Setup:

```bash
python -m pip install -e .[dev]
```

Run:

```bash
python -m momentum_lab.main
```

Tests:

```bash
python -m pytest -q
python -m momentum_lab.eval
```

RL report regeneration:

```bash
python -m momentum_lab.rl.train --no-train --no-eval
```

RL interactive replay/story viewer (read-only over `runs/rl`):

```bash
# Top-N + curated progression story, human run as the reference line:
python -m momentum_lab.rl.visualizer --top 24 --story progression --reference 750982
# Materialize a rollout for a saved model that has none, then view it (needs SB3):
python -m momentum_lab.rl.visualizer --reevaluate runs/rl/models/<model>.zip
```

Writes `runs/rl/analysis/replay_viewer/index.html` (open off `file://`).

RL training-trace recorder (opt-in intra-run "learning over steps" timeline; off by
default because it adds an eval rollout to disk per interval):

```bash
# Save a ppo_trace rollout at step 0 and every --trace-eval-freq steps while training:
python -m momentum_lab.rl.train --keep-best --save-trace-checkpoints --trace-eval-freq 10000 ...
# Then watch the timeline (the traces are ordinary artifacts the viewer selects):
python -m momentum_lab.rl.visualizer --model <model-stem> --policy ppo_trace
```

Use `python -m pytest`, especially before editable install, so the working tree is
on `sys.path`.

## Non-Negotiable Invariants

- `Simulation.step()` takes an `Action`, not `dt`.
- `core/` must not import pygame, input polling, rendering, file I/O, wall-clock
  time, RL training code, or generated artifacts.
- Sim time is `tick * CONTROL_DT`; do not use wall-clock time inside the sim.
- Keep same-machine determinism. If randomness is added, seed it from
  `reset(seed)` and snapshot it.
- Input goes through `Action`. Do not add direct key-to-physics paths.
- Replays, ghosts, scripted evals, and RL all drive the same control-rate `Action`
  stream.
- Track geometry is immutable once loaded and can be shared by snapshots.
- Derived metrics such as slip angle, drift time, wall stats, path distance, and lap
  progress must not feed back into physics.
- Snapshot/restore must include every stateful thing needed for branching and
  replay validation.
- Changing physics behavior/constants should update `PHYSICS_VERSION` and relevant
  tests/eval expectations.

## Task Guidance

Physics/car feel:

- Tune through `momentum_lab/eval/harness.py` and `python -m momentum_lab.eval`.
- Keep drift emergent from local-frame velocity/grip.
- The fast technique should be drift-and-catch, not holding handbrake forever.
- Constants live in `CarPhysics`; changing them can invalidate ghosts.

Collision/raycasts:

- Walls are line segments; the car is a circle.
- Use swept collision/resolution.
- Preserve tangential velocity, remove into-wall normal velocity, and distinguish
  impact from scrape by normal speed.
- Keep raycasts pygame-free.

Checkpoints/timing:

- Gates are directed line segments. `Gate.from_endpoints` defines direction by
  rotating the endpoint tangent +90 degrees.
- Timer starts on first non-zero throttle.
- Only the next checkpoint advances progress.
- Finish closes only after all checkpoints are cleared.
- Timing is tick-derived, never wall-clock.

Tracks:

- Top-level JSON tracks are loaded by `momentum_lab/tracks/loader.py`.
- Validate loudly at load time with `TrackError`.
- Track 1 geometry should be edited in `tools/build_track_01.py` and regenerated.

Rendering/UI:

- Renderer reads sim state and never mutates it.
- Real-time pacing, pygame events, and live tuning belong outside `core/`.

Replay/RL:

- Canonical replay is seed + initial state + action stream.
- Position frames are derived caches for cheap visualization.
- Store/compare `physics_version` and physics fingerprint.
- Reward versions must map to exactly one constant set. Bump reward versions when
  constants change.
- Reward totals are comparable only across the same reward version unless re-scored.

## Definition Of Done

- Relevant tests for the changed contract pass.
- `python -m pytest -q` passes unless a real blocker is documented.
- Run `python -m momentum_lab.eval` for physics, track, wall, checkpoint, lap-feel,
  or timing changes.
- Update `BACKLOG.md` when task status, scope, priority, or acceptance changes.
- Update `docs/PROJECT_STATE.md` when current truth or durable architecture changes.
